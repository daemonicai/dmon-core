- **[architect]** Decisions taken for this block, all recorded here because none is in `design.md` yet:
  - **Swift 6 language mode**, not dmonium's 5.9. Toolchain on this machine is Swift 6.3.3 / Xcode 26.6. PRD §4.3 permits `@unchecked Sendable` and `nonisolated(unsafe)` *"at the ring buffer boundary, where a safety property is being asserted that the compiler cannot see"* and warns that their appearance elsewhere means "a concurrency diagnostic has been suppressed rather than a problem solved" — a constraint that is only meaningful under strict concurrency checking. Choosing 5.9 now would silently void PRD §4.3 before the audio phases start.
  - **One `home/Package.swift` with three library targets**, not three separate packages. PRD §2.3's table says "packages"; targets give the same module seam and import boundary, with one manifest to maintain and a single `swift test --package-path home` that mirrors the existing `daemon-app-test` pattern. XcodeGen wires one local package rather than three.
  - **`make dmon-home` / `make dmon-home-test`**, named for the product, mirroring `daemon-app` / `daemon-app-test`. Must not disturb the existing pair (design D9 / spec "The existing Swift app is untouched").
  - **The generated `.xcodeproj` is gitignored**; `home/project.yml` is the source of truth. `.gitignore:90` already ignores `daemon/Daemon.App/.build/`, so the `home/` equivalents go alongside it.
  - **Seeded, not stubbed.** `specs/dmon-home/spec.md` forbids a package existing "solely as a placeholder for a later phase", and SPM requires every target to have at least one source file.
