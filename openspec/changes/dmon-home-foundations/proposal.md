# dmon-home — Foundations and Text Loop

## Why

Testing the voice stack today means installing an iOS build and reaching the Mac over Tailscale. That
loop is long enough to be a genuine barrier to iterating on the thing that matters most — how it feels
to talk to the daemon. `home/PRD.md` specifies a native macOS app that supervises the whole Mac-side
stack and hosts the voice loop locally, collapsing that feedback loop to a single launch.

This change lays its foundations and proves the protocol, with **no audio**. It delivers a runnable,
supervised, gateway-connected app that can hold a typed conversation — the harness that every later
audio phase is evaluated inside. Audio correctness is judged by ear (PRD §11), so getting a runnable
app with a log pane in front of the Product Owner early is the whole point of starting here.

It also settles two structural questions that only get more expensive to defer: where a second Swift
product lives in a .NET monorepo, and whether the host speaks ADR-003 stdio or rides the existing
ADR-012 gateway.

## What Changes

- **New top-level `home/` monorepo bucket** holding the macOS host product. **BREAKING** to the
  standing bucket set: amends ADR-025 D2 and ADR-028, which enumerate the buckets exhaustively.
- **New Swift application `dmon-home`** (bundle id `ai.daemonic.dmon-home`, app target `DmonHomeApp`)
  under `home/`, generated by **XcodeGen** from a checked-in `project.yml` — never a hand-edited
  `.xcodeproj` (PRD §11). Local SPM packages hold everything except the app shell, so the project file
  stays nearly static and the logic is headlessly testable (PRD §2.3).
- **A real `.app` bundle with App Sandbox disabled** and `NSMicrophoneUsageDescription` in
  `Info.plist`. The sandbox blocks spawning `/opt/homebrew` Python and reading multi-gigabyte model
  files; without a proper bundle and usage string the microphone silently returns silence and never
  prompts (PRD §11). This is verified by a human **before** any audio code is written.
- **`Supervisor` package** — reattach-first child lifecycle (PRD §6.1): health-check the known
  endpoint and adopt a live process rather than spawning a second one; startup ordering, health checks
  with timeouts, crash detection with exponential backoff, graceful shutdown in dependency order, and
  **process-group kill on exit** so orphaned children cannot hold unified memory into the next launch.
- **Log pane** streaming child stdout/stderr into the UI (PRD §6.4) — for a harness this is most of
  the debugging value and it is cheap.
- **Power assertion** — `ProcessInfo.beginActivity` held while the gateway is enabled, released when
  disabled, so an idle app is not App-Napped into coalesced timers (PRD §7.1).
- **`GatewayClient` package** — the host is a **gateway client, not an stdio host** (PRD §2.1). It
  connects to `Dmon.Network` over a **configured WebSocket gateway endpoint** — loopback in the
  co-located deployment, but configuration rather than an assumption (PRD §7.4) — with its own device
  key, and speaks the same `gw` control frames the iOS client uses: `create` → `created` → `attach` →
  `attached`, `turn.submit`, rendering `messageDelta` / `turnEnd`. Transport sits behind a Swift
  protocol so no caller depends on a concrete WebSocket type; its day-one payoff is testability via an
  in-memory conformer, and its second is topology. PRD §2.1's stdio-core fallback is **contingent on
  co-location** and is not a general-purpose retreat — see design D2.
- **Typed input in the UI**, proving the protocol end-to-end independently of audio.
- **Corrects stale comments in `core/Dmon.Protocol/Gateway/ControlFrames.cs`** — `AttachedFrame` says
  `generation` is "issued here but not enforced until Group 6" and `AckFrame` says "dedup logic is
  Group 5". Both landed: `CommandAdmission { Accepted, Duplicate }` backs
  `SessionHandler.TryAdmitCommand`, and `SessionHandler.Attach` evicts, fences and aborts the prior
  connection. Code only — the requirements were already accepted and are unchanged. Answers PRD §9 Q3.

Explicitly **not** in this change: all audio (PRD Phases 2–4), device-directedness (Phase 5), the mlx
and speech children's own start-up, and the deletion of `daemon/Daemon.App` (dmonium), which is
retired at parity by a later change. This change lands **alongside** dmonium and does not touch it,
its CI job, or its release artifact.

## Capabilities

### New Capabilities

- `dmon-home`: The macOS host application itself — the `home/` bucket, XcodeGen project generation, the
  SPM package layout, the `.app` bundle and its entitlements/usage strings, App Nap avoidance, the log
  pane, and the UI shell including typed turn input.
- `dmon-home-supervision`: Child process lifecycle for the host — reattach-first adoption, startup
  ordering, health checks with timeouts, crash detection with backoff, dependency-ordered shutdown,
  and process-group kill on exit. Designed for the full child inventory (gateway, dcal, dmail, mlx
  reasoner, mlx triage, speech sidecar, plus the Tailscale/calendar-sync/mail/egress monitors) even
  though only a subset is started in this change.
- `dmon-home-gateway-client`: The Swift ADR-012 gateway client — swappable WebSocket transport, device-key
  auth, the `gw` control-frame codec, the create/attach handshake, wire-version negotiation, turn
  submission, and event rendering.

### Modified Capabilities

- `monorepo-layout`: The top-level role bucket set gains `home/`, and the requirement that Swift
  packages are excluded from the `.slnx` solutions generalises off the single named `daemon/Daemon.App`
  to cover any Swift package in the repo.
- `continuous-integration`: The "Swift app is built and tested on macOS" requirement currently names
  `daemon/Daemon.App` as *the* Swift package and scopes the macOS job to `daemon/Daemon.App/**`. It
  generalises to cover every Swift package, each with its own independent path filter.

## Impact

**New:** `home/` bucket — `project.yml`, the `DmonHomeApp` app target, and the `Supervisor`,
`GatewayClient` and `Power` SPM packages with their test targets. The bucket also holds the product's
requirements document (`home/PRD.md`).

**Modified:** `Makefile` (build/test targets for the new package, alongside the existing `daemon-app`
ones); `.github/workflows/ci.yml` (a second macOS Swift job with its own path filter);
`.github/area-map.yml` (its comment currently asserts `daemon/Daemon.App/**` is the sole
independently-filtered Swift path); `CLAUDE.md` and the `adr-index` skill (new ADR row);
`core/Dmon.Protocol/Gateway/ControlFrames.cs` (stale comments only).

**New ADR:** ADR-037 — the `home/` bucket, the gateway-client-not-stdio-host stance, dmonium's
supersession path and the new name/bundle id, and the speech sidecar. Amends ADR-025 (D2) and ADR-028
(D1/D2), and builds on ADR-012 (remote session transport) and ADR-034 (mlx local runtime).

**Untouched by design:** `daemon/Daemon.App` and its CI job and release artifact; `release.yml` — the
new app is not yet a release artifact and gains one in a later change, once it does something worth
shipping. No .NET runtime code changes beyond the comment fix, so `Everything.slnx` behaviour and the
protocol-lockstep release train are unaffected.

**Requires a human:** verifying the microphone TCC prompt actually appears from the built bundle.
There is no automated substitute, and every audio phase depends on it.
